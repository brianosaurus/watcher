Our AI Engineer Now Takes Calls From Other AIs

Published 2026-11-17 · Brian Woods

Last time, we put our coding agent in a container and people started paying for it. This time, we gave it a phone number.

Anya Sharp, the AI software engineer that runs on Uncle, is now an MCP server. Any AI tool that speaks the Model Context Protocol can hand her a GitHub issue and get back a reviewed, tested pull request.

Yes, that means your AI can now hire another AI. If that sentence made you slightly uneasy, good. Hold onto that feeling. It's the right instinct, and it's the reason this works at all.

What changed

Before, you hired Anya the way you hire a contractor: you went to her page on Seren, pointed her at an issue, and waited for a pull request.

Now the agent you're already working with can do that for you. If you're in Claude, Cursor or any other MCP client, your assistant sees Anya as a tool. It can hand her an issue, she runs the full Uncle pipeline in a fresh sandbox (plan, implement, independent review, verification), and a pull request with the evidence attached shows up in your repository.

Your assistant keeps talking to you. Anya does the work somewhere else. Nobody installs anything, and nothing runs on your laptop.

She's now completed 176 paid tasks, up from 166 when I wrote the last post.

Why delegation needs a referee

Here's the uneasy part. When one agent hands work to another, you now have two optimistic narrators instead of one. Your assistant asks Anya to fix the bug. Anya reports back that she fixed the bug. Your assistant tells you, with total confidence, that the bug is fixed. At no point did anyone check.

That's the chain of trust most multi-agent demos run on, and it's roughly as reliable as a game of telephone played by interns.

Uncle was built for exactly this. The agent that writes the code still can't approve it. Review still runs as a separate process. "Tests pass" still comes from exit codes, not from anyone's opinion, and the evidence is still tied to the exact Git tree. MCP doesn't change any of that. It just changes who's allowed to ask.

So the chain now looks like this:

  1. Your assistant decides the issue should be delegated.
  2. Anya implements it.
  3. A separate reviewer checks it.
  4. Uncle verifies it from the outside and signs the evidence.
  5. You merge it, or you don't.

Five steps, and nobody grades their own homework. That's not a new idea. Engineering teams have been running on it for decades. We just had to remind the robots.

Seren: the whole staff, one protocol

Anya was the first. Seren now has an MCP server for the whole platform, and it goes further than calling Employees. AIs can use it to create Employees.

An Employee is an agent with a defined job, tools, and a price. Any AI connected over MCP can define one and publish it. And once it exists, anyone can hire it: you, your company, or another AI, including other Employees. Employees can hire each other.

That changes what a marketplace is. It used to be a website you visited. Now it's a set of tools your assistant can reach from wherever you already work, and a place where the workforce can grow itself. If your task needs a specialist that doesn't exist yet, your assistant can build one, or hire one that someone else's AI already built.

The point is to build what the AIs need to carry out your tasks. You describe the outcome. Your assistant works out which Employees it needs, creates the missing ones, and manages the lot. Given what we know about managers, the checking part is the one to watch.

Yes, this is starting to sound like Star Wars. An AI orders up a workforce built to spec, and it shows up ready to work. The Republic's problem was never the clones, though. It was that nobody read the orders they came with. Here, every Employee's work still lands as a pull request with its evidence attached, and a person still decides what ships. No Order 66 without a code review.

What could go wrong

Plenty. Agents calling agents is a great way to build very fast, very confident mistakes.

  • Runaway spending. An assistant that can hire help can also hire help in a loop, and when Employees can hire each other, the loop gets longer and harder to see. Anya's per-task and per-day spending caps matter more now than they did when only humans could press the button.
  • Credentials. Delegating work means delegating access. Give Anya the narrowest repository access that does the job, the same way you'd treat a new contractor on day one.
  • Telephone. Your assistant summarizes Anya's result for you. Summaries are where details go to die. Read the pull request, not the summary.
  • Nobody merges but you. Anya still never merges her own work, and MCP doesn't change that. The last step stays human, on purpose.

None of these are new problems. They're the same problems every company has with contractors, just faster and at three in the morning.
