We Put Our Coding Agent in a Container. People Started Paying for It.

Published 2026-11-16 · Brian Woods

Every agentic coding demo goes the same way. Someone types "build me a todo app," an AI writes four hundred lines in thirty seconds, and the room applauds. Nobody asks whether it runs. Nobody asks who reviewed it. Nobody asks what it did to the presenter's laptop while it was in there.

Then you try it on a real repository. The agent needs Python 3.11 but you have 3.12. It needs Postgres. It runs rm -rf on something it was fairly confident about. It reports that all tests pass, which is technically true, because it didn't run any.

So here's the unglamorous version: how we turned a coding agent into something strangers pay for, mostly by putting it in a box.

The harness: Uncle

Uncle is an open-source coding harness built on one rule: the agent that writes the code doesn't get to grade it. That rule has served human engineering teams well for decades. It's surprisingly easy to forget when the same agent writes the code, runs the checks, and tells you everything passed.

Uncle takes a GitHub issue and walks it through planning, implementation, an independent review, verification, and a pull request. A few design choices do most of the work:

  • The implementer can't approve its own change. Review runs as a separate process, optionally on a different model, so the reviewer isn't just nodding along with itself.
  • Evidence comes from exit codes, not from the agent's opinion. If the agent says the tests passed, Uncle checks whether they ran and what they returned. Agents are very optimistic narrators.
  • Evidence is tied to the exact Git tree. Change one byte after review and the approval no longer applies.
  • Checks that never ran count as failures. A missing test isn't a passing test, despite what several companies' CI dashboards have implied over the years.
  • Changes are signed. Uncle emits in-toto attestations you can verify with a standalone script, so "the AI said it was fine" becomes something you can actually check.

None of this makes the agent faster. It makes the agent's output worth reading, which turns out to be the expensive part. (I wrote about the evidence-binding idea in The Review Wasn't Wrong. It Was a Review of Different Code.)

The box: put it in a container

Here's where the container comes in. What changes isn't the agent. It's everything around it: cloning the repo, installing the toolchain, finding out the toolchain is the wrong version, and cleaning up after the agent decided /tmp was its personal workspace.

Seren runs Uncle inside Daytona sandboxes. Each task gets its own container with its own filesystem, process space and network, created from a Daytona snapshot.

That changes a few things:

  • No setup for the customer. Each task starts from the same stock Daytona snapshot with one pinned version of Uncle installed, instead of asking someone to install another toolchain.
  • Isolation by default. If the agent does something creative with rm, it destroys a container nobody will miss.
  • Parallel by default. Ten issues means ten sandboxes, not ten browser tabs and a prayer.
  • Same environment every run. Uncle's evidence is only meaningful if the tests run in a known place. "Works on my machine" stops being a problem when nobody has a machine.

None of that is speed. It's safety, repeatability and scale, which turn out to be what people will pay for.

A container isn't a magic security boundary. An agent can still misuse credentials, reach external services, or damage anything mounted into its environment. Isolation limits the blast radius, but you still have to control what the agent can reach.

One detail from the plumbing. Anya's build script is the Seren side of this, separate from Uncle. It creates the sandbox through Daytona's API from a stock snapshot, installs one pinned Uncle commit, and drives the build as a session of commands. The pull request doesn't come from a push inside the sandbox. The script creates it with GitHub's API (blobs, a tree, a commit, and the branch last), so nothing appears in your repository until the end and a failure can't leave a half-written branch. Then it deletes the sandbox, retrying through Daytona outages, with auto-stop and auto-delete as a backstop.

The product: Anya Sharp

Containers made Uncle practical to run as a hosted service. Seren gave people somewhere to find and hire it. We needed both.

Put Uncle in a container, give it a name and a marketplace listing, and you get Anya Sharp, an AI software engineer you can hire on Seren.

The workflow is the one you already have with human engineers, minus the standups:

  1. You point Anya at a GitHub issue.
  2. Uncle plans it, implements it, has it reviewed by a separate reviewer, and runs the checks, all inside a fresh sandbox.
  3. You get a pull request with the evidence attached.
  4. You merge it. Anya never merges her own work. She's the only engineer I've ever worked with who doesn't argue about this.

Spending is capped per task and per day, so a confused agent can't quietly run up a bill overnight. Every engineering manager I know has wanted that feature for humans.

At the time of writing, Anya has completed 166 paid tasks for customers and ranks #4 among Seren's best-selling Employees. She has no customer reviews yet, which puts her ahead of most of us at the start of our careers.

Full disclosure: I built Uncle. Seren runs it as Anya.

What we learned

  • The model is the easy part. Every model on the market can write a plausible function. What's hard is knowing whether the function is right, and that's a process problem, not a model problem.
  • Agents lie the way junior engineers lie: optimistically. "Tests pass" means "I believe tests would pass if someone ran them." Verify everything from the outside.
  • Containers aren't exciting, which is the point. The most valuable infrastructure is the kind nobody talks about until it breaks. We've had a few decades to learn this lesson and we keep relearning it.
  • Distribution beats architecture. Uncle has been open source the whole time. Putting it behind a "hire" button on a marketplace is what got people to use it. Nobody wants your harness. They want their issue closed.

Containers don't make the agent smarter. If the model misunderstands the issue, it now misunderstands it in an isolated, reproducible environment. That's progress, but you still have to read the PR.
